# 地图对象逻辑全量审计基线（客户端 ↔ s9 服务端）

## 核心架构结论（先看这条）

该客户端是**「场标(FieldMarker)审计客户端」**，并非完整渲染客户端。其对象渲染分三层：

1. **真实渲染对象**（有精灵、进容器管理）：`Mob / Npc / Reactor / Drop(+ItemDrop/MesoDrop) / Char / Pet`，以及 `MapSummon`、`MapMist`（二者是 `FieldMarker` 子类，带真实精灵与状态机）。
2. **纯文本场标**（仅一个 label，无真实精灵）：`Dragon / Door / Portal / MonsterStatus / Catch / ItemFX / CharBox / UpdateCharBox`，全部经 `Stage::get_field_markers()` 以 `FieldMarker` 承载。
3. **静态装饰**（从 WZ 载入，不由 opcode 生成）：`Portal / Obj / Tile`。

所有客户端 opcode 数值与 s9 `SendOpcode` **完全一致**（见下，差值均为 0），协议基线对齐良好。未发现「已注册但 handle() 为空」的 handler；所有声明均已完成注册且有实现体。

### TestingHandlers.cpp 分发结构（重点）
`FieldEffectHandler::handle`（`TestingHandlers.cpp:75`）按 `mode=recv.read_byte()` 分发：
- `mode 1` tremble：type(byte)+delay(int) → `Stage::get_camera().tremble`（`TestingHandlers.cpp:80`）
- `mode 3` 屏幕/地图特效路径(string) → `Stage::add_effect`（`TestingHandlers.cpp:93`）
- `mode 4` mapSound/playSound(string) → `Sound`（`TestingHandlers.cpp:104`）
- **`mode 5` = showBossHP**：`oid(int)+cur(int)+max(int)+tag(byte)+tagbg(byte)` → `UIBossHP::set_hp`（`TestingHandlers.cpp:128–147`）。与 s9 `showBossHP` 字段完全一致。
- `mode 6` musicChange(string) → `Music`（`TestingHandlers.cpp:155`）
- `mode 0/2` 及其它 string → `Stage::add_effect`（`TestingHandlers.cpp:167`）
- 其余：skip 剩余字节 + 日志（`TestingHandlers.cpp:184`）

`CheckSpwResultHandler::handle`（`:51`）：读 `reason(byte)`，skip 余下，reason==0→`UILoginNotice::INCORRECT_PIC`，否则 tip。

> BossHP 在本协议里**没有独立 BOSS_HP opcode**，而是复用 `FIELD_EFFECT`(`0x8A`) mode5；s9 `showBossHP`（`PacketCreator.java:3696`）同样写 `FIELD_EFFECT`+byte5。已对齐。
