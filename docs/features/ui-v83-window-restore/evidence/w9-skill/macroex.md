# R14-2F「技能组合栏内部 UI 也有缺失」— 量取与结论

截图依据：`native-refs-r14/` 全 20 张里**没有**原生「技能宏指令窗口 / 技能组合栏」。
逐张对 `UIWindow.img/SkillMacroEx/backgrnd`（181x303）做粗搜（`_r16_scan.txt`）：
最低 SAD=18.2 落在 `3fe4ade2` 的 (573,117) —— 那是**我们自己的客户端**渲染（英文
`MacroEx — SoftKey name` 占位），不是原生。其余 26~37 都是浅灰底的无关命中。
⇒ 本窗内部件只能从**烘焙图素**反推；图素给不出的（按钮位、快捷键、Macroicon 归属）
一律显式预留，不猜。

## 1. backgrnd 量取方法

`tools/nx_inspect.py list UIWindow.nx … SkillMacroEx` → `backgrnd` **181x303、origin (0,0)**
⇒ 图素像素坐标 == 窗口坐标（`DrawArgument::get_rectangle`：可见左上角 = 绘制点 − origin）。

测量脚本（本目录外，一次性）：`_r15_me_layout.py`（逐行内容段）、`_r15_me_bottom.py`
（底部面板）、`_r15_me_frame2.py` + ASCII 亮度图（`_r15_me_art.txt`，判底部标签/白框）。
内容判据：`alpha>40 且 lum<240`。

## 3. 已实现（`IO/UITypes/UIMiscShells.cpp` `UISkillMacroEx`）

1. 删掉英文占位 `tip_label`（用户看到的「内部 UI 缺失」主因就是它 + 空槽无图标）。
2. 5 行 × 3 格 = `SkillMacros` 的 5 个槽位（`skill1/2/3`），图标按格子中心居中绘制：
   `topleft = (cell_x + cell_w/2, row_top + 18) - dim/2 + origin`。
   格子中心 x = 28 / 64 / 101。
3. 宏名画进白框：A11M `linespace=17`、SimHei 11px 汉字 `bitmap_top=11`
   ⇒ 墨迹顶 = draw_y + 6；白框 14 高、墨迹 11 高 ⇒ 墨迹顶 253 ⇒ **draw_y = 247**；
   左缘 53 + 2px 内边距 = **draw_x 55**（内边距未取证，取保守值）。
   当前只绑 1 号槽（`send_key` 的 S/R 改名的就是 slot 0），行选中态待原生取证。
4. 反馈文案改走 `LOG(LOG_INFO/LOG_WARN)`，不再往窗体上刷英文。

## 4. 显式预留（缺证据，不动）

| 预留项 | 阻塞原因 |
| --- | --- |
| `BtSave`(35x18「保存」) / `BtMacroIn`(47x18「宏指令▶」) / `BtMacroOut`(47x18「宏指令◀」) 的落位 | 181x303 图素内**没有**容得下 35x18 / 47x18 的空位（面板内已被标签+白框占满，行区被 3 格+菱形+快捷键框占满）⇒ 原生是画在窗体外的独立件，偏移只能靠原生截图或 IDA |
| 行右侧快捷键白框的文字 | `SkillMacroSlot` 无 hotkey 字段；`MACRO_SYS_DATA_INIT` 里是否带快捷键待封包侧确认 |
| `Macroicon/0..4/{icon,iconDisabled,iconMouseOver}`（32x32）的归属 | 32x32 在图素里找不到对应空槽；候选是「行首槽位底」或「底部个性技能预览」，二者都会被烘焙标签压住 ⇒ 需原生截图 |
| 行选中 / 点击改槽位 | 需要按钮命中区，同上 |

要推进第 4 节，最小成本是补一张原生「技能宏指令窗口」整窗截图（含窗体下沿的按钮）。
