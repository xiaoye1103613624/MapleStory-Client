## 5. §2 第 2 项的结论（**本轮推翻重写**）：框体是 `Basic.img/Notice4`，不是平涂

> 本节原结论（「全 UI.nx 扫描零命中 ⇒ 框体是按行平涂」）**是工具 bug 造成的误判**：
> 旧脚本用 `ntype == 2` 筛位图，而 nx 的位图类型码是 **5**（2 是 double）。所以那次
> 「零命中」根本没匹配到任何一张图。改用 `nx.name(i)` + `ntype==5` 重扫后，
> 266 宽这一档的框族一直在 `Basic.img` 里。

逐行按色 + 位图像素比对（脚本 `E:/project/_ms_probe/utildlg-lookup.py`，输出
`_ms_probe/_utildlg_lookup.txt`）把截帧每一行钉到具体帧：

| 截帧行 | 命中 |
| --- | --- |
| y=5 | `Basic.img/{Notice3,Notice4,Notice5,YesNo3}/t!r6@x0`（三族 t 同形，取 266 档 = Notice4） |
| y=42..44 | `Notice4/s!r0,r1,r2,r22` |
| y=45 / 46 / 47 | `s!r3` / `s!r4` / `s!r10..r16`（输入框黑上沿就是 s 的第 4 行） |
| y=63 / 64 | `s!r21` / `s!r0,r1,r2,r22` |

### 8.3 本轮为过这一关改的三处（都是命中/焦点，不是排版）

1. **聊天栏目标列表点不动**（第一次真机跑出来的现象：列表能开、点行没反应）。
   根因在派发：`UIStateGame::send_cursor` 用 `is_in_range` 选元素
   （[IO/UIStateGame.cpp:564](../../../../../IO/UIStateGame.cpp#L564)），而列表画在聊天栏
   矩形**上方**，`UIChatBar::is_in_range` 不含这块 ⇒ 点击漏给场景。
   修：列表打开时把该矩形并入命中区。
2. **点了箭头之后回车不生效**（弹层不关、也不回填）。根因：
   `UI::send_cursor` 在「按下点落在 focusedtextfield 的 bounds 外」时直接把焦点指针清空
   （[IO/UI.cpp:162](../../../../../IO/UI.cpp#L162)），而 `Textfield` 自身 `state` 仍是
   FOCUSED ⇒ 之后 `set_state(FOCUSED)` 是空操作，焦点回不来，回车走全局派发被丢。
   修：输入框命中区给成**整条 ComboBox**（含右端 18px 箭头），下拉打开时再一路盖到
   最后一行；另加 `refocus_field()`（先 NORMAL 再 FOCUSED 才能真正重新登记）。
3. **ESC 两级退出挂在字段上**。焦点在输入框时按键走
   `UI::send_key → focusedtextfield->send_key`（[IO/UI.cpp:236](../../../../../IO/UI.cpp#L236)），
   根本进不到窗体的 `send_key`，所以「先收列表再关窗」必须挂在
   `name_field` 的 ESCAPE 回调上，窗体 `send_key` 里那份只作脱焦后的兜底。

### 8.4 已知残余（不阻塞 B5-2，留 B8 收尾）

- 列表打开时，点到**聊天栏与列表矩形之外**（场景/其它窗体）不会收起列表，
  要点回框体或按 ESC。修法要么扩 `is_in_range` 到全屏（会吞一次地图点击），
  要么把列表做成独立 UIElement —— 两者都超出本批「按原生逻辑把列表选出来」的范围。
