## 5. §2 第 2 项的结论：UtilDlgEx 的 frame 件里没有 261 宽这一档

`nx_inspect` 全 `UI.nx` 扫描（depth≤3，宽 250..275）**零命中**；`UtilDlgEx` 自己的
frame 件全是 529 宽这一档：

```
it 529x28   t 529x28        ic 529x20   c 529x20        is 529x58   s 529x58
notice 311x134   bar 121x19   line 332x2   list0 119x14  list1 102x18
list2 26x14  list3 106x14(-1,0)   dot0/dot1 6x7
UtilDlgEx_Avatar/backgrnd 419x306   UtilDlgEx_Pet/backgrnd 419x296
UtilDlgEx_MultiPetEquip/backgrnd 419x219
```

⇒ 原生这层窄弹层的框体**不是**整张 frame 贴图，而是「按行平涂 + 自己的高光边」拼出来的
（§1 的逐行读数就是这个形态：蓝面板行 9..76 全是平涂色，没有斜切/花纹）。
所以本端落法：**按 §4 的实测色值平涂 + 上/下 1px 高光边 + 直接用 `BtOK`/`BtNo` 位图**，
不硬套 529 宽的 `t/c/s`（硬套要么溢出 268px，要么被裁成没有右沿）。
`ComboBox` 一族在 `Basic.img` 里有 `ComboBox`..`ComboBox5`（五态齐全）+ `BtComboBox`
（四态），下拉那 10x19 箭头列从这里取，不必自绘。
