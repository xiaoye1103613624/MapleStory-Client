## 1 三层底板叠放顺序：逐带配准钉死

整窗 SAD 配准在 Messenger 上是**误导**的：`backgrnd` 与 `backgrnd2` 在 y0..25 完全同色，
`backgrnd` 的 y0..239 又被 `backgrnd2` 盖住，所以整体 SAD 会同时给两个候选。
改用**分带配准**（只看某一层未被遮挡的带），在窗口原点 (0,6) 处结果：

| 带 | 取自 | SAD |
| --- | --- | --- |
| y0..104 | `backgrnd2` | 13.15 |
| y148..239 | `backgrnd2` | **6.06** |
| y240..363 | `backgrnd` | **5.59** |
| y0..104 | `backgrnd`（预期更差：被盖住） | 30.98 |

偏移 ±1 行时全部劣化（y=5 → 23.61/23.89/20.91；y=7 → 24.59/24.42/17.54），
所以窗口原点就是 (0,6)，且**预测的非对称出现了**：被盖住的 `backgrnd` 上半 SAD 明显更差。

⇒ 结论：`backgrnd(0,0) → backgrnd2(0,0) → backgrnd3(55,22)` 的现有绘制顺序**是对的**，
不需要改。`backgrnd3` 另有一处独立佐证：参考图里白色页签的上下黑边在
local y24 / y41、x58..231，而 `backgrnd3` 画在 (55,22) 正好罩住 x55..238 / y22..43 ✓。

## 2 切片逐行分区（决定各元素该落在哪）

对切片本身逐行取色（x6..289，避开窗框），run-length 分类：

**`backgrnd`（295×364）**

| y | 分区 |
| --- | --- |
| 0..18 | 标题条 |
| 26..117 | TAN 面板 |
| 118..120 | 分隔带 |
| 121..143 | TAN 面板（续） |
| **150..301** | **WHITE 大框** |
| 302..340 | 输入槽区（黑框 y317 / y333，x9..245） |
| 341..363 | 底带 |

**`backgrnd2`（295×240）**：y0..25 与 `backgrnd` 逐行同色；26..48 TAN 页签轨；
**56..177 WHITE**；178..215 输入槽区（黑框 y193 / y209，x10..246）；217..239 底带。

关键推论：`backgrnd2` 比 `backgrnd` 的对应结构整体上移 **124 行**
（302−178 = 217−93… 逐段核对均为 124）。`backgrnd2` 只有 240 高，盖住 `backgrnd` 的
y0..239，于是**聊天历史可见白框 = y240..301（62 行）**，而不是 `backgrnd` 自己的 150..301。

参考图独立验证：整图 WHITE 连续带正是 ref y246..307 → local **240..301** ✓。

## 4 改动

`IO/UITypes/UIMessenger.h` 新增版式常量（窗口内坐标，逐条对应 §2/§3）：

```cpp
CHAT_LOG_TOP = 231;        // 字形顶 = 231 + 10 = 241，落在白框 y240..301 内
CHAT_LOG_LINE_H = 14;
CHAT_LOG_VISIBLE = 4;      // 4 行 → 字形 241..296，离框底 301 还留 5
CHAT_INPUT_X = 12;  CHAT_INPUT_Y = 318;  CHAT_INPUT_W = 228;  CHAT_INPUT_H = 15;
CHAT_INPUT_TEXT_SHIFT_Y = -9;   // 与 UIChatBar 同一套（真机验过）：把字形从 bounds 顶 +10 抬回槽内
BT_ENTER_X = 245;  BT_ENTER_Y = 322;
```

`IO/UITypes/UIMessenger.cpp`：

1. `draw()`：历史行只画 `chat_labels` 尾部 `CHAT_LOG_VISIBLE` 行，首行 y 由 204 → 231；
   `chat_log` / `chat_labels` 仍按 `CHAT_LINES = 8` 保留滚动缓冲（不满 4 行时自上而下填）。
2. `update()`：`chat_input` bounds 由 `(14, 330, 225×16)` → `(12, 318, 228×15)`，
   即命中区与美术框内沿重合。
3. 构造：`Textfield` 传 `marker_height = 11`（与 UIChatBar 一致）并 `set_text_shift(0, -9)`；
   删掉「按实际高度重定位输入框」的二次构造（那一段只是把同一个框用 `dimension` 反推一遍，
   而本窗 `dimension` 就是 `backgrnd` 的 295×364，反推出来的 330 正是错的值）。
4. `BtEnter` 位置 → `(245, 322)`。
5. 移除因此不再使用的 `#include <algorithm>`。

## 5 已知不足 / 显式预留

- **原生还有一个输入槽没实现**：`backgrnd2` 里烤死的黑框 y193..209 / x10..246（成员区正下方）。
  原生在此处另有控件，但本包 Messenger 节点里没有任何标签能指认它的用途，
  `chatBalloon`（46×36，5 帧）与 `blink`（12×10）也都还没接。
  **本版不凭猜测补控件**，只记录为预留项（见 `notes/open-issues.md`）。
- 聊天文字左缩 x=16 未改：白框横向铺满 x1..293，原生留多少内缩无像素证据（框内无文字样例）。
- 历史行距 14 沿用改前值：参考图这张截图的白框是空的，测不到原生行距。
- 无 `ida-pro-mcp`，`UIMessenger` 的控件清单/回调无法从二进制侧确认。
