# 底栏气球锚定判据（目录 / 界面）— R27-B6

用户报「目录列表位置不对」。这一条此前**没有尺**（`r27-oracle/README.md` 记过：原生那张
`目录按钮点击后的列表.png` 只有 82x182，比 `GameMenu/backgrnd` 93 宽还窄，`anchor_in` 判模板过大），
所以 B6 一直只做气球**内部**栅格（4 颗钮 @(8, 22+26i)），**落位**没动。

本轮找出一条不需要整张底板对帧的尺，两条独立截帧互证，落位进门禁。

## 1. 判据：尖角最后一条实像素行贴在触发钮上沿

93 宽的气球底板自带向下的下摆尖角（`GameMenu/backgrnd` alpha 收到 x45..47，尖端中心 x=46），
原生把它摆在**触发它的那颗底栏钮**正上方。竖直方向到底贴在哪一档，两张截帧给的是同一个答案：

| 截帧 | 气球画布末行（尖角最后一条实像素行） | 触发钮掩膜配准命中 | 间隙 |
| --- | --- | --- | --- |
| `目录按钮点击后的列表.png`（82x182） | crop y **142** | `StatusBar.img/BtMenu/normal/0`（54x34，origin (0,0)）命中 crop **(16,143)**，掩膜 SAD 20.14 | **1 行** |
| `”界面“按钮点击后的列表.png`（94x278） | crop y **243** | `StatusBar.img/BtShort/normal/0` 命中 crop y **244**，掩膜 SAD 41.92 | **1 行** |

SAD 20/42 按定版规则属**不可信量级**（截帧里气球被半透明底压暗），所以这两条只用来钉 **y 栅格**；
x 方向不进判据（第二张的 SAD 41 连列都不可信）。真正定 x 的是尖角中心 x=46 对准钮中心。

换算成客户侧算式：底条顶 = `VHEIGHT - 71`（`UIStatusBar::CLASSIC_BAR_H`），4 颗功能钮画在底条
rel y=36（IDA `CreateCtrl` y=543，底条顶 507），故**钮上沿绝对 y = VHEIGHT - 35**，
气球顶 = `VHEIGHT - 71 + 36 - 气球高`。

> 旧算式是 `VHEIGHT - 71 - 气球高`，即把尖角停在**底条上沿**，比原生**高 36px**。
> `UIShortCut::update_screen` 与本轮新增的 `UIGameMenu::update_screen` 共用这套几何，两条一起改
> （`w1w3-hud/coords.md` T-2b 里那条 `position.y = VHEIGHT - 71 - 245` 同步作废）。

## 2. 为什么客户帧不能用整张 backgrnd 配准（抓到的假FAIL）

先按 oracle 的老办法拿 `GameMenu/backgrnd`（93x140）在真机帧上做掩膜配准，结果：

```
GameMenu/backgrnd: sad=36.67 agree=0.835  art origin(view)=(180,-19)   <- 飘到别处
BtMenu/normal    : sad=61.15 agree=0.581  上沿 view y=685  中心 x=767.5 <- 命中的是 BtShort(741..795)
```

半透明深蓝底板的 masked mean-SAD **没有判别力**：最低点落在无关的暗区，而 4 颗底栏钮彼此同形，
`BtMenu` 那颗被 `BtShort` 抢走（中心 x=767.5 正是 group_x+168+27）。这种尺写进门禁只会造假 FAIL。

改用的尺是气球**内部** 4 颗 `81x25` 蓝钮的行剖面 —— 蓝 `(0..51, 102..119, 187..238)` 在原生帧和
我们帧上都是实心高对比，掩膜 `b>=140 && b-r>=40 && g>r` 逐行找**宽度 79..83 的连续列程**，
堆出 25 行高的段。判据三件：

1. 恰有 4 段 25 行、步距恒 26（= `GameMenu` 版式 `(8, 22+26i)`，`gamemenu-balloon.md` §2 的同一把尺）；
2. 气球左上角 `(首段列 - 8 - 8, 首段行 - 22 - 31)` == 期望 `(666, 545)`，tol 2px；
3. 尖角末行 `top+139` 与钮上沿 `VHEIGHT-35` 的间隙 == **1**（§1 那条原生判据）。

> 「找 81 宽列程」而不是「找蓝色像素的 min/max 列」：第 4 颗钮下面就是底栏自己的蓝色，
> 整行取 min/max 会把两段并成一条 190 宽的段（实测 y676..705 就是这样），25 行的段高判据当场失效。

同一条列程还要再补两个动作，界面气球才认得齐 8 颗（都是这一轮帧上量出来的，不是猜的）：

- **宽度封顶的贪心合并**（`col_runs(max_gap=12, max_width=83)`）：钮上的文字笔画把 81 宽蓝带切成
  `12+1+8+3+4+42`（界面第 3 颗 capture y=550），不合并只认到 5 颗；但只按间隙合又过头 ——
  目录第 4 颗 capture y=690 左边 7px 处另有一段蓝（650..674，底栏邻件），拼成 113 宽后被
  `79..83` 过滤器整段判死。封顶 83（「一颗钮最宽也就 81±2」）两头都能卡住。
- **候选取「离众数列程最近」，不取第一个**：界面第 8 颗 capture y=694 那行，底栏自己的蓝件
  正好也是 79 宽（647..725），按顺序取会串台、把段劈断。众数 = 全帧出现行数最多的列程，
  也就是那条钮列本身，仍然从帧里读。

## 3. 第二把尺：底板剪影（不依赖内部栅格）

蓝钮行法把气球顶算成「首颗钮顶 − 22」。这个 22/26/x=8 本身是有据的（[../w2-hud-buttons/shortcut-balloon.md](../w2-hud-buttons/shortcut-balloon.md)
§1：界面气球 7 件 `SAD=0.00` 精确命中，等差推出 `y = 22 + 26i`、`x = 8`、共 8 颗），但它终究是
**内部栅格**的读数——万一内部摆错，落位会被一起带偏。所以另加一把只读底板自身像素的尺，与内部栅格无关：

`未开帧` 与 `气球帧` 逐像素做差（`|ΔRGB| > 18`），取窗口上界截在底栏钮上沿（不吃底栏自身变化），
从窗口最底往上收「一条比一条窄」的行 —— 那就是 alpha 叠出来的下摆尖。量两件事：

1. **尖端末行 view y** 应 == `BTN_TOP - 1 = 684`（§1 的原生判据，间隙 1）；
2. **尖端中心 x − 46** 应 == 期望气球左上角 x（`TAIL_CX = 46`，93 宽画布的对称中心）。

实测（`--tail`）：目录尖 view `(712, 684)` → `712-46 = 666` = 期望，Δx=**0**；界面尖 view `(768, 684)`
→ `768-46 = 722` = 期望，Δx=**0**。两把尺的 x 相差 1px（蓝掩膜左右各掉一条反列），来源彼此独立。

## 5. 踩过的坑

- **进图后第一次点击被客户端吞掉**：实录 `_b6_run_log.txt` 里 `try0` 点完帧里没有气球，
  `try1` 才画出来（项目记忆 live-client-verification-gotchas 那条「首个按键 ~3s 内被丢」在鼠标上重演）。
  驱动现在按判据断言并重试（`02_open_tryN`），不再假设「点一下就开」。
- **「再点一次钮收起」不成立**：第三次点击后气球仍在（`log: after click#3 balloon_open=True`）。
  `UIGameMenu::FOCUSED = true`（[UIMiscShells.h:596](../../../../../IO/UITypes/UIMiscShells.h#L596)），气球激活期间鼠标事件被它吃掉，
  底栏 `BtMenu` 收不到第二下 —— 实际关窗路径只有 ESC（`UIGameMenu::send_key` 的 escape 分支）。
  原生这颗钮能不能二次点击收起，属只能用户取证，归 B7（「ESC 开目录 / 关目录」一并验）。
- 实例退出：`WM_CLOSE` + 对同 pid 的顶层窗口 `PostMessage` 回车，本轮实例已自行退出（未强杀任何进程）。
- **判据太脆会把「已经画对」的气球判成「没开」**：同一份 `_b6_run_log.txt` 里 `05_shortcut` 三次点击
  全报 `not open` 后 ABORT，而那几帧气球其实都在、落位也正 —— 是「8 段 25 高」这条计数被钮上的
  文字笔画（少认 3 颗）和同宽的底栏蓝件（串台）打穿。判据修好后，同一批归档帧离线重算即 8/8 OK
  （`_b6_recheck.txt`），所以日志那句 `not open` 是**修判据之前**的产物，别拿它当结论。
  教训：「窗未开」和「版式不符」不能共用一个退出码，否则尺一坏就把功能判死。
- 界面气球 `try2` 帧底部三行整段找不到 81 宽列程（只认到 7 段），`try0` 帧 8 段齐 —— 取 `try0` 作准；
  底部被什么遮了未查清（不影响锚定：剪影尺只看尖角，`try0` 上 Δx=0、间隙 1）。
