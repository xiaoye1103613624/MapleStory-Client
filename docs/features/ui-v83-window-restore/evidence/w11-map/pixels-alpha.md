## 2. 决定性证据：钮区颜色计数对上素材

区域 (104,8)–(142,22) 抓帧直方图：

```
(103, 71,  8) × 210
(119,111,103) × 130
(103,103,103) × 104   <- 钮四周的 Min/c 底
(  0,  0,  0) ×  88
```

`UIWindow.img/MiniMap/BtMap/normal/0`（36×12）素材自身直方图：

```
(221,153, 17) × 210   橙底
(255,238,221) × 130   高光
(  0,  0,  0) ×  88   烤死的「大地图」黑字
(  0,  0,  0) ×   4   透明边
```

**逐色像素个数完全一致（210/130/88）**，只是每个非零通道同乘 **0.466**：

| 素材 | ×0.466 | 实测 |
| --- | --- | --- |
| 221 | 103.0 | 103 |
| 153 | 71.3 | 71 |
| 17 | 7.9 | 8 |
| 255 | 118.8 | 119 |
| 238 | 110.9 | 111 |

同帧 `Min/c` 素材 (221,221,221) → 实测 (103,103,103)，系数一致。

0.466 ∈ [0,1) 且逐帧锯齿 → 就是 `MapleStory.cpp` 的 `accumulator / timestep`。
结论：不是素材代次差异、不是 PrintWindow 合成，而是 **UI 层把帧插值系数当不透明度**。
（`IO/UIElement.cpp:52-57` 的 `draw_buttons()` 丢弃形参，所以按钮 RGB 本身是不透明写入；
它之所以在抓帧里也暗，是底下被半透明画过的 `Min/c` 把后缓冲 alpha 写成了 0.466。）
