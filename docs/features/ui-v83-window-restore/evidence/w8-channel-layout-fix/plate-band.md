# R28-B1 UIChannel 逐格复核：先推翻我上轮的三条结论

复核方法（这次不再靠肉眼并排）：把 `_dump/` 里的原始位图按候选常数**合成**出一张 436×121 的窗体，
再和原生帧 `C:/Users/11036/Desktop/正确客户端截图/频道变更.png` 逐行求 SAD。合成→比对可在不改代码、
不起客户端的前提下把常数钉死，比"抓帧后目视"强一档。

坐标系（沿用 [channel-layout.md](../w7-option-channel/channel-layout.md) §1，本次二次独立确认）：
原生帧 428×122 是**裁过的**，**帧坐标 + (3, 1) = 窗坐标**。`channel0` 在帧 (216,66)/(286,66)/(356,66)
逐像素 SAD=0.000 ⇒ 窗坐标 (219,67) = `9 + 70·i`，`i=3,4,5`。

## 0. 撤回上轮的三条误判（都错，写在前面）

| 上轮我说 | 实测 |
| --- | --- |
| 「板 x 基址要从 9 改成 6」 | **错**。6 是直接拿帧像素 x 当窗坐标、漏了 +3 裁切。`9 + 70i` 本来就对，改回去反而整体左偏 3px。 |
| 「世界条比原生高约 4px」 | **错**。窗坐标 y=3..66（标题行 + 蓝色世界名条）合成帧与原生帧 **mean SAD = 0.00**，逐像素全等。 |
| 「原生世界条左端的蜗牛图标我没画」 | **不存在这个件**。`world/0` 就是「蓝蜗牛」三个字的位图（48×18），已画且位置对（窗 (16,31)）。帧左上角那条彩色是我误读了裁切外的背景。 |

⇒ 教训：**"元素在位"不等于"版式修好"，反过来"看着不对"也不等于真不对**。判据只能是合成帧逐行 SAD。

## 1. 真缺陷只有三条，全在槽行以下

原生帧窗坐标逐行 residual（合成帧 vs 原生帧，mean SAD）：

| 行段 | 现象 | 根因 |
| --- | --- | --- |
| y=67..87 的**板缝**（窗 x=77,78 / 147,148 / 217,218 / 287,288 / 357,358）与**最右板以右** x=427..430 | 原生是纯白 (255,255,255)，我的实现透出身后的场景 | **槽行没有底板**。`Channel` 根没有 `backgrnd`，白底来源是 `c`（436×10 纯白细条，430 个不透明像素，左右各留 3px 透明边）。按 10 行平铺到条带顶即闭合。 |
| 条带描边行 | 原生深色描边行（`s` 的第 6 行）在 **y=94**，我画在 93 | **`s` 条带顶是 y=88，不是 67+20=87**。槽行与条带之间原生多留 1 行白（y=87 实测 255）。 |
| 窗体下缘 | 原生不透明内容到 **y=120**；121/122 已是窗外（(87,87,87)/(112,112,102) = 背景） | `s` 名义高 36，**实测只有前 33 行不透明**（第 33~35 行全透明）。`dimension` 用 87+36=123 ⇒ 高了 2 行，底部两行吃掉点击区。 |

两颗橙钮：`BtChange` 窗 (286, 99) SAD=0.20、`BtCancel` 窗 (380, 99) SAD=0.22（90×16 邻域搜索最优）
⇒ 相对条带顶偏移 = 99 − 88 = **11**（旧代码写 12，是跟着 `s`=87 一起错的）。

## 2. 合成帧回归（改常数前后的对照）

同一张合成画布，只换条带顶与钮偏移：

| S_Y | 钮 dy | c 平铺行数 | mean SAD | >12 的像素数 |
| ---: | ---: | ---: | ---: | ---: |
| 87 | 12 | 2（不铺白底） | **17.02** | 5536 |
| 88 | 11 | 3 | **5.99** | 1377 |

逐行 residual（S_Y=88 / 钮 11 / c 平铺 3）：y=3..71、82..98、118..120 **全部 0.00**。

残余的两处不是版式问题，是 `_dump/` 导出件的像素差，已确认与客户端无关：

- y=72..81（`ch/0..2` 标签，窗 x 17..36 / 87..106 / 157..176）：偏移搜索 lx∈[13,22]、ly∈[68,77] 的最优
  就是 **(17, 72)**，位置对；差异只在字身像素（白字带描边，dump 出的那份与原生渲染态不同源）。
- y=31,32,48（`world/0` 蓝蜗牛）：同上，位置 (16,31) 是 6×7 邻域搜索最优。
