参考截帧：`C:\Users\11036\Desktop\正确客户端截图\目录按钮点击后的列表.png`（**82×182**）
素材：`UI.nx` → `UIWindow.img/GameMenu/`（`backgrnd` **93×140 origin(0,0)**；`BtChannel/BtGameOpt/BtSysOpt/BtSkin/BtQuit` 各 81×25、4 态）

## 1. 行为判定：目录 → 主菜单气球是**原生正确**行为

用户报「『目录』点击后显示主菜单，这不对吧？」。截帧本身给出答案：原生点「目录」弹出的就是标题为「主菜单」的气球，内含
**频道变更 CHANNEL CHANGE / 游戏设置 GAME OPTION / 系统设置 SYSTEM OPTION / 游戏结束 GAME QUIT** 四颗钮。
所以缺陷不在行为，只在**我们的版式**（5 颗、步距 20）。

> 另注：旧的「点目录同时弹 UIOptionMenu」双开行为已在 `UIStatusBar.cpp:719-738` 的
> `BT_CLASSIC_MENU` classic 分支修掉（只开 `UIGameMenu`）。

## 3. crop ↔ 画布坐标映射

crop 只有 82 宽（画布 93）、182 高（气球 140 + 底栏钮），说明是手工截取、两侧不对齐。两条独立证据：

- **x**：钮体蓝色几乎铺满扫描窗 x 2..79（实心行 77/78）→ 钮左沿 ≤ crop x1。整颗 81 宽不可能在 82 宽 crop 内居中（居中需 crop x0.5 起，画布却 93 宽）。故 crop **左沿落在画布左沿之外**。
- **y**：crop 下摆区 128..142（15 行）与画布下摆 131..139（9 行）对齐后，尖端 crop 142 紧贴底栏钮顶 143（无缝）→ **画布 y = crop y − 3**。

于是 **画布 x = crop x + 7**。
