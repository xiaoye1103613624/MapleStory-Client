# R24 逐像素取证：NPC 对话正文框、任务窗蓝横幅立绘格、素材覆盖率

## 1. NPC 对话立绘不该镜像（`_r24_0002101.png`）

从 `Npc.nx / 0002101.img / stand / 0` 原样导出（56×55，未做任何处理）。
**希娜原图就是朝右、面向正文的**，而原生 528×261 参考帧把她摆在窗口左侧 ⇒
`UINpcTalk` 里恒传 `flip=true` 会把她翻成背对正文。修法是去掉这个常量翻转，
不是换图、不是挪坐标。

> 这条曾经差点按子 agent 的一句话直接改：先回退、导出原图看过、确认朝向，才重新落这个改动。

## 2. 对话正文块几何（原生 528×261 参考帧）

壳体外缘在参考帧 x6 y5，换算到窗口自身坐标：

| 量 | 值 | 旧实现 | 后果 |
| --- | --- | --- | --- |
| 正文左上 | (122, 35) | 滑块态 (162, 19) / 普通态 (166, 48−(h−min)) | 普通态一拉长就整体上移贴窗框 |
| 折行宽度 | 387（右缘 x509） | 320，起笔 x162 ⇒ 右缘 x482 | 正文压到右下角「确定」(471..517) 上，看着像"按钮位置不对" |
| 翻页步长 | `height − 18`（可见高） | 固定 400px | 可见区最多 230px，每翻一页跳过约 170px 正文 |
| 命中区高 | `top + body + bottom` (=h+86) | `height + 120` | 底部 30 余px 空白白吞点击 |

按钮本身（CLOSE x9 / OK x471）与参考帧只差 ±2px，**不是**按钮坐标错，是正文压过去了。

## 3. 任务窗蓝横幅 = 标题区 + 立绘格（`_r24_bg2_measure.txt`）

`_r24_q_bg2.png` 是 `UI.nx / UIWindow.img / Quest / backgrnd2`（305×396）原图，
按颜色阈值扫出横幅几何（脚本口径见 `_r24_bg2_measure.txt`）：

```
banner rows   y 26..118
full cols     x 16..297
divider col   x 190          ← 左=标题/正文，右=NPC 立绘格
```

`bg_right_pos.x() = 243` ⇒ 立绘格在**窗口坐标 x433..540、y26..118**，
`UINpcTalk` 同一取法（`Npc/<7位id>.img/stand/0`）把图按脚底锚点落在格底 y112。

同目录 `_r24_q_bg1.png` = `backgrnd`（245×396），两张拼起来 548×396，
正是原生 `R_quest.png` 的整窗尺寸 —— 这也是判定 `dimension` 该是 548 而不是 307 的依据。

## 4. 「NPC/怪物没有显示」不是缺素材（`_r24_artcover.txt`）

把 5364 张地图的 `life` 全量清点，和随包美术根对集合：

```
map imgs = 5364   with life = 3097
art roots: Mob.nx = 2053   Npc.nx = 7198

MOB  地图上摆的 distinct id = 827    缺美术 = 0   (0.0%)
NPC  地图上摆的 distinct id = 1280   缺美术 = 1   (0.1%)  ← 只有 id 2104，出现在 1 张图
```

⇒ 这一类现象的真因是**落位**（服务端 spawn 包 y 槽传的是 wz 的 `cy`，客户端又拿
`get_y_below` 反查一遍，把自家平台判成"不够低"而掉到下一层，反查不到就被丢到 borders 外），
不是资源缺失。修法见 `NpcSpawn::instantiate` 改走包里声明的 `fh`。

脚本：`scripts/artcover.py`（只读，走 `tools/nx_inspect.py` 的 Nx）。
