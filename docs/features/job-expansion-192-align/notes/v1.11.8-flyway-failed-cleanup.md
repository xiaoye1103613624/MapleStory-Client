# Flyway 失败记录清理（V1.11.8）

若服务端已因错误列名跑挂 `V1.11.8`，Flyway 通常会在 `flyway_schema_history` 留下 **success=0** 的失败行，之后即使 SQL 文件已修好也会拒绝继续迁移。

**本说明只给用户手跑的 SQL；Agent 未连库执行 DDL/DML。**

## 1. 先查失败记录

```sql
SELECT installed_rank, version, description, type, script, checksum, installed_on, success
FROM flyway_schema_history
WHERE version = '1.11.8'
ORDER BY installed_rank;
```

## 2. 删除失败记录（仅当 success=0）

确认是失败行后再删：

```sql
DELETE FROM flyway_schema_history
WHERE version = '1.11.8'
  AND success = 0;
```

若误插入了半成品 `game_config` 行（一般本失败发生在 INSERT 解析阶段，通常无半成品），可再核对：

```sql
SELECT config_code, config_value
FROM game_config
WHERE config_code IN ('enable_evan', 'enable_dual_blade');
```

修好的迁移带 `WHERE NOT EXISTS`，已有行也不会重复插入。

## 3. 重新启动

1. 确认磁盘上 `V1.11.8__enable_evan_dual_blade.sql` 已是修正版（列名为 `config_sub_type` / `config_clazz` / `config_code` / `config_desc`）。
2. 按原方式启动 s9 服务端，让 Flyway 重新执行 V1.11.8。
3. 启动成功后再查：

```sql
SELECT version, success, installed_on
FROM flyway_schema_history
WHERE version = '1.11.8';

SELECT config_code, config_value
FROM game_config
WHERE config_code IN ('enable_evan', 'enable_dual_blade');
```

期望：`success = 1`，两条 config 均为 `'true'`。
