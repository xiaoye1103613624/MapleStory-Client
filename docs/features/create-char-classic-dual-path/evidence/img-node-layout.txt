### 说明板自带「选择按钮槽」（像素证据）
导出 normal/text/0 后放大观察：板右下有一个白色圆角矩形按钮槽，
板内左上约 (412,111)、尺寸约 73x29 —— 与 BtSelect/normal/0 的 73x29 完全一致。
板绘制原点 = 窗口内 (118,311)（IDA sub_6157C9 的 v79/v80），
故白槽中心/左上换算到窗口坐标 = (118+412, 311+111) = (530,422)，
正好是 IDA 中 CCtrlButton::Create(this, 1003, 530, 422, ...) 的 BtSelect 位置。

### 结论：说明框位置正确，「选择」按钮位置不对
UICommonCreation / UIRaceSelect 里 BtSelect 是手工
std::make_unique<MapleButton>(src, classic_select_pos)，未走
MapleButton::try_maple_btn 的 `position + origin` 补偿。
Texture::draw 以 (pos - origin) 作位图左上，于是按钮被画到
(530-36, 422-14) = (494,408)，比白槽左移 36px、上移 14px。
→ 按钮浮在说明板中部，白槽裸露（截图里那块浅色/蓝色矩形）。

avatarSel / charSet / statTb / 各按钮均无 pos / ctrl 定位向量，只有位图尺寸与 origin。
→ 外观面板的「精确落点」没有节点位置信息，只能用位图尺寸 + 窗口尺寸推导。

### 5.1 节点时序（上一轮记「无 delay」有误，此处更正）

  scroll/0 (展开): 0=242x30 delay=250, 1=242x214 delay=50,
                   2=242x212 delay=50, 3=242x210 (末帧定格)

### 5.2 量测输出摘要

  charSet 225x377 主色 (255,255,221)

    → disabled 为深棕禁用底色（本轮按外观池大小判定该行是否可切换）；

  BtCheck 50x24 / BtLeft,BtRight 15x16 / BtYes,BtNo 81x41，origin 全 (0,0)
  statTb 65x77 = 「力量/敏捷/智力/运气」四属性表
  charAlert 187x120 白底提示框；charName 201x224，输入槽板内 (28,102) 150x25

### 5.3 结论

`pos` 向量缺失不等于位置信息缺失：位图内的烘焙槽位、内容区边界、按钮尺寸、
帧 delay 与 origin 共同构成 step4 板内坐标证据。逐控件对照见
`notes/native-step4-layout.md`。屏幕绝对落点仍无原生证据，已在对照表 §5
标为低置信度推导值与决策点，不伪装成原生常量。
