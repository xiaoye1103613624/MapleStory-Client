## 1. 职业团选择页 Login.img/RaceSelect

RaceSelect [null]

  aran / aran1 / knight / normal [null] ; 每个含 text/0 说明板

  aran/text/0    [bitmap] 579x163 origin (0,0)

### 说明板自带「选择按钮槽」（像素证据）
导出 normal/text/0 后放大观察：板右下有一个白色圆角矩形按钮槽，
板内左上约 (412,111)、尺寸约 73x29 —— 与 BtSelect/normal/0 的 73x29 完全一致。
板绘制原点 = 窗口内 (118,311)（IDA sub_6157C9 的 v79/v80），
故白槽中心/左上换算到窗口坐标 = (118+412, 311+111) = (530,422)，
正好是 IDA 中 CCtrlButton::Create(this, 1003, 530, 422, ...) 的 BtSelect 位置。

### 结论：说明框位置正确，「选择」按钮位置不对
UICommonCreation / UIRaceSelect 里 BtSelect 是手工
std::make_unique<MapleButton>(src, classic_select_pos)，未走
MapleButton::try_maple_btn 的 `position + origin` 补偿。
Texture::draw 以 (pos - origin) 作位图左上，于是按钮被画到
(530-36, 422-14) = (494,408)，比白槽左移 36px、上移 14px。
→ 按钮浮在说明板中部，白槽裸露（截图里那块浅色/蓝色矩形）。

### 名字吊牌输入槽（像素证据）
导出 charName 后放大：深棕色横向输入槽位于板内左上约 (28,102)、
尺寸约 150x25。代码 slot_pos(28,104)、newCharNameDim(150,24) 与节点吻合。
字体为 A12M（约 12px），24px 槽需 set_text_shift 做基线补偿才能垂直居中。

### 节点缺失（R6，属预期）
CustomizeChar、RaceSelect_new、Common/BtPreview、NewChar/createLimit 为 <absent>；
avatarSel / charSet / statTb / 各按钮均无 pos / ctrl 定位向量，只有位图尺寸与 origin。
→ 外观面板的「精确落点」没有节点位置信息，只能用位图尺寸 + 窗口尺寸推导。

编号对应关系由 UI.nx 的 Login.img/RaceSelect 视差条目确认：
  MapLogin.img/back/41 -> no 16
  MapLogin.img/back/45 -> no 30
  MapLogin.img/back/39 -> no 33

LoginBackground::set_scene(src,pos) 内 scene_pos = pos + src.origin()，
Sprite::draw 再减 origin，最终位图左上 = 调用方传入的 pos。
因此 scene_pos 与 avatar_pos 必须用同一套「屏幕左上」坐标系比较。
