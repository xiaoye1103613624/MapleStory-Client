## 三、阻塞点（本轮未闭环的三项，附根因）

1. **GM 命令全灭**：`CommandsExecutor.loadCommandsExecutor()` 体内的
   `registerLv0..Lv3Commands()` **全部被注释**，`registeredCommands` 是空 HashMap
   （`CommandsExecutor.java:73-78`）。`isCommand()` 只看 `isGM()` 决定允不允许发 `!`，
   但命令表空 ⇒ `!warp` / `!lvl` 静默无效（无报错、无回包）。
2. **客户端 GM 包与服务端 ops 不匹配**：客户端 `AdminEnterMapPacket` 用
   `Mode::ENTER_MAP=0x11`，服务端 `AdminCommandHandler` 的 `switch(mode)` 只认
   `0x00 刷怪 / 0x01 清包 / 0x02 设置经验` 等，无 0x11 ⇒ 现有 GM 按钮走不到服务端分支。
   若要用 0x00 刷怪造测试怪，需客户端新增对应包（服务端能力在，客户端未接）。
3. **换图只能改库**：角色地图持久化在 `characters.map`（`Character.java:7895` 写回）。
   把角色挪到有怪地图需 DML ⇒ 按门禁 17 未获授权不动库。

### 6.1 途中纠正的两个自身错误（防复发）

1. **误用 admin 门**：先用 `Configuration::get_admin()` 做门，导致自驱动静默不发。根因——服务端 admin 位 =
   `(use_enforce_admin_account||canFly) && GMLevel>1`（`PacketCreator.getAuthSuccess:741`），本机 DB 种子该开关为 false
   且账号未 IP 放行 ⇒ admin 位 false；而服务端 `AdminCommandHandler` 自己的门是 `isGM()`（GMLevel>0），两者不等价。
   去掉该误门后立即打通。**今后任何"客户端 GM 能力"判断都不要用 get_admin()。**
2. **exe 时间戳倒挂**：中途见到 `PROBE_OK` 就以为构建生效，实际 exe(11:47) 早于源码(11:50)——旧 exe 跑出"SMOKE 一行都没有"的假象。
   与既有铁律同源：**A/B/冒烟前必须核 exe mtime ≥ 源码 mtime**。
