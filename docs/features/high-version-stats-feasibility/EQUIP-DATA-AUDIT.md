## 2. 为什么不是"全量补 24820 件"

客户端 `Character.nx` 是 192 高清版资源，含 29,821 件装备美术；服务端 s9 是 v83 精简逻辑，原本只配了 ~6000 件 XML。两者差 24820 件里绝大多数是**客户端有美术但服务端游戏逻辑从不发放**的装备（没有 drop、不在商店、不在任何套装）——补了也是死数据。

真正有害的是"服务端功能会引用、但缺白值"的装备。权威判定源是 **DB `xy_set_item` 的 item_ids**（61 个启用套装 = 玩家实际会穿的套装装备）。这批 454 件里补前缺 449 件，是本次的补齐范围。

### 3.2 批量补的 433 件
来源：61 个启用套装引用的 item_ids 中缺 XML、且客户端 nx 有模型的装备。
生成规则（属性驱动，不臆造）：
- 遍历客户端 `Character.nx/<类别>/<id>.img/info` 的所有子节点
- int → `<int name=... value=.../>`；string → `<string .../>`；vector → `<vector x= y=/>`
- real → 转 int（装备字段均为整数）
- 每个 XML 用 `xml.etree.ElementTree.fromstring` 校验通过才写盘
- 输出到服务端 `wz/Character.wz/<类别>/<id>.img.xml`（jar 外部明文目录，重启即生效，无需打包）

补后各目录 XML 数：Cap 951、Weapon 1397、Accessory 537、Longcoat 532、Shoes 463、Coat 464、Glove 280、Cape 209 等（总计 5437，补前约 6000 是因为部分目录 Hair/Face 本就齐全未动）。

### 3.3 无法补的 16 件（幽灵 id）
`05000084/05000089~93/05000203~205/05000212~214/05000234~236/01360258` 等——客户端 Character.nx **全目录搜索无模型**。这些是套装表引用但当前客户端无美术的 id（192 端可能有、移植时未带，或数据错误）。补 XML 也无法显示，建议后续清理套装表引用或补美术资源。
